# Evaluation

This directory builds and audits the versioned BPMN benchmark and the E8
refinement cases. [`METHODOLOGY.md`](METHODOLOGY.md) defines eligibility,
operators, ground-truth construction, and review rules. The stored dataset
layout is documented in [`data/eval/README.md`](../data/eval/README.md).
Executed studies belong to [`experiments/`](../experiments/README.md).

```text
data/pmo-dataset/       local, read-only source corpus
  -> eligibility probe lossless import, round trip, Tier 1, Tier 2
  -> generator         deterministic STRUCT and SOUND mutation + inverse repair
data/eval/v1.0/         versioned seeds, variants, descriptions, and ground truth
  -> experiment specs  frozen panels and model configuration
experiments/results/    raw observations, provenance, and analyses
```

## Commands

Run commands from the repository root:

```bash
make eligibility-probe OUT=/tmp/bpmn-probe
make dataset-build \
  PROBE=data/eval/v1.0/probe.json \
  OUT=/tmp/bpmn-eval \
  VERSION=v1.0
make dataset-audit DATASET=data/eval/v1.0
make enhancement-build
make enhancement-audit TIER2=off
```

The probe is provider-free and must be rerun when parser or Tier 2 coverage
changes. The build is deterministic for its stored seed and selection rules.
`dataset-audit` verifies file hashes, path joins, expected findings, mutation
replay, and inverse repairs. `enhancement-audit` checks the separately stored E8
construction without sending a model request.

## Stored snapshots

The final `data/eval/v1.0/` snapshot contains 43 eligible seeds, 313
deterministic structural or soundness variants, 198 human-verified semantic
single variants, and 37 verified disjoint semantic pairs. The manifest is the
authoritative source for these counts and file hashes. Semantic construction
and review provenance is described in
[`data/eval/v1.0/SEMANTIC.md`](../data/eval/v1.0/SEMANTIC.md).

The E8 slice at `data/eval/enhancement/` contains 21 requirement-driven
refinement cases. Each case keeps the core diagram shown to the evaluated
model, the held-out instruction, a clean reference, deterministic relation
contracts, preservation IDs, and an oracle plan used only for construction and
audit.

## Ground-truth join

The runner deliberately has no ground-truth logic. A trial records an
`input_path` and input hash. Analysis removes `variants/` and the file extension
from the path, then resolves the same relative identifier under
`ground_truth/`. For example:

```text
variants/interacting/S03+S03/55.bpmn
ground_truth/interacting/S03+S03/55.json
```

The same identifier is also used under `descriptions/variants/`. Exact path
matching prevents a result from being scored against the wrong mutation.

Human-reviewed semantic variants are audited from their versioned artifacts;
they are not regenerated by asking another model. Do not overwrite `v1.0` after
a methodological change. Create a new dataset version and retain the old one.
