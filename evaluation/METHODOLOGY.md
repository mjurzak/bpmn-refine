# Defect Injection Methodology

This document defines dataset and ground-truth construction. Exact executed
configurations and result artifacts are mapped in
[`experiments/README.md`](../experiments/README.md).

The benchmark is stored at `data/eval/v1.0/`; its on-disk layout is specified in [`data/eval/README.md`](../data/eval/README.md).

Scope: dataset `v1.0`, built from the PMo Dataset only, with English descriptions. The eligibility probe (`evaluation/generator/probe.py`) admits 43 of the 55 PMo models as seeds. [`data/eval/v1.0/EXCLUSIONS.md`](../data/eval/v1.0/EXCLUSIONS.md) records the twelve exclusions and is generated by the probe. Every admitted seed has an English description.

The current IR excludes collaborations, lanes, sub-process bodies, data objects, and artifacts. Event definitions retain their kind, identifier, and attributes; nested details such as timer schedules remain unsupported. The importer reports each unsupported child, and the probe excludes the affected source model. PM4Py's BPMN-to-Petri conversion does not represent intermediate catch events or complex gateways, so the probe records `tier2_unsupported` for models 25, 30, 37, 42, and 44 instead of assigning a soundness verdict.

Vocabulary: a *seed* is a clean source model, a *defect operator* is a rule for introducing one fault, and a *variant* is a seed with one or more injected defects.

The catalogue and the generated dataset are frozen before any prompt work, and dataset versions are recorded separately from prompt versions in every run block.

The benchmark has one dataset version: `v1.0`.

## 1. Operators must be grounded outside the detector

An operator defined as the inverse of one of my own rules measures whether that rule detects its own negation. Every operator therefore cites a source independent of this implementation, and the [operator catalogue](#3-operator-catalogue) records that source per operator.

Three classes, with decreasing strength of claim:

- `STRUCT` violates a BPMN 2.0.2 structural constraint represented by tier 1. These cases calibrate the pipeline; they are not evidence of semantic or formal reasoning.
- `SOUND` violates workflow-net soundness. These operators are the ones the counterexample ablation rests on.
- `SEM` contradicts the process description. The reference is natural language, so the [semantic layer protocol](#6-semantic-layer-protocol) covers it separately.

I do not claim these defects reproduce the frequency distribution of errors made by human modellers. That claim needs an observational corpus, which `v1.0` does not include.

## 2. The expected finding is derived from the operator

Woflan is tier 2 of the system under evaluation, so it cannot also decide whether a variant is faulty. Each operator instead carries an applicability condition and the finding that follows from its definition. Applying `F02` to a sound, well-formed seed produces lack of synchronisation by the Sadiq and Orlowska result, whether or not any checker runs. The generator writes that finding into the ground-truth record at construction time.

Determinism of the checker does not remove the need for this. Even where Woflan returns the same verdict for the same input, that says nothing about whether the verdict is correct. The recorded expectation is what makes a tier-2 false negative observable: without it, a miss and a genuine SOUND verdict produce the same output and cannot be told apart. One such divergence is already known, since pm4py encodes uncontrolled splits as free choice and Woflan then reports SOUND on a model with contradictory end states.

Seeds must be clean before injection: no tier-1 findings, and SOUND under tier 2. Two further conditions come before those, because a model that fails them cannot be injected into at all: the importer must keep every child of the source file, and the IR must survive its own export unchanged apart from layout the source never carried. Models failing any of the four move to `wild/` with the failing stage recorded, and are never used as seeds.

A fifth outcome is neither pass nor fail: tier 2 can return no verdict, by timing out or by crashing inside the checker. That leaves soundness unknown rather than false, so those models are excluded under their own reason and not counted as unsound.

Collaborations require a checker that represents message-flow synchronisation. The current probe excludes them at the lossless-import gate, before tier 2, so Woflan never assigns a soundness verdict to a collection of participants treated as one control-flow process.

PM4Py connects BPMN start events to one Petri-net source and end events to one sink. Extra structural sources or sinks remain visible to Woflan. The probe runs each model in a separate process so a timed-out Woflan worker cannot prevent the corpus report from completing.

## 3. Operator catalogue

| id | class | operation | grounding | expected finding |
|---|---|---|---|---|
| `S01` | STRUCT | delete the only start event while an end event remains | BPMN 2.0.2 §10.5.2, p. 237 | `R001` |
| `S02` | STRUCT | delete the only end event while a start event remains | BPMN 2.0.2 §10.5.3, p. 245 | `R002` |
| `S03` | STRUCT | repoint a sequence flow at an absent element id | BPMN 2.0.2 §8.4.13, Table 8.51, p. 97 | `R005` or `R006` |
| `F01` | SOUND | close an XOR split with an AND join | Sadiq and Orlowska (2000) | deadlock |
| `F02` | SOUND | close an AND split with an XOR join | Sadiq and Orlowska (2000) | lack of synchronisation |
| `F03` | SOUND | delete a merging gateway, leaving concurrent paths at the end event | van der Aalst (1997) | improper completion |
| `F04` | SOUND | delete a bridge flow, leaving a downstream region unreachable | van der Aalst (1997) | dead transition (`R007`) |
| `M01` | SEM | delete a task realising a described action | [protocol](#6-semantic-layer-protocol) | `missing_step` |
| `M02` | SEM | swap two tasks whose order the text fixes | [protocol](#6-semantic-layer-protocol) | `contradictory_flow` |
| `M03` | SEM | negate a gateway condition stated in the text | [protocol](#6-semantic-layer-protocol) | `unreachable_branch` |
| `M04` | SEM | delete a described exception path | [protocol](#6-semantic-layer-protocol) | `missing_exception_handling` |
| `M05` | SEM | rename a task to a term the text uses for another object | [protocol](#6-semantic-layer-protocol) | `inconsistent_naming` |
| `M06` | SEM | make a described end state unreachable | [protocol](#6-semantic-layer-protocol) | `improper_termination` |
| `M07` | SEM | add one reachable business action that contradicts an explicit prohibition or outcome | [protocol](#6-semantic-layer-protocol) | `unwanted_action` |

Which elements a finding must point at depends on the injection site, so that part of the ground truth lives in the per-instance record.

The `STRUCT` clauses were checked against the local BPMN 2.0.2 specification PDF. The dataset contract intentionally defines `S01` as removing a start event and `S02` as removing an end event, independently of which opposite boundary remains. Consequently, `S01+S02` expects both configured checker findings, `R001` and `R002`. Direct Woflan execution also reports such a model as unsound, but construction-time detection for `STRUCT` variants records tier 1 only.

Operators act on the IR, not on XML. Most injections use production `EditOp`s; `S03` uses a generator-local endpoint mutation because production repair operations must not create dangling references. Every ground-truth repair remains a production `EditOp` plan. The stored repairs restore control-flow semantics; layout comparison uses the matching seed model because `AddNodeOp` and `AddFlowOp` do not restore BPMNDI geometry. Defects outside the IR vocabulary (duplicate `xsd:ID`, malformed XML) belong to a separate `malformed/` set that exercises the import guard.

Semantic categories match `app/validation/rules.py:SemanticCategory`. If that enum changes, this table and the dataset version change with it.

## 4. Variants that leave the verdict unchanged

A variant that is still sound and still consistent with its description is equivalent to its seed. Discard it and record the operator and site that produced it.

A variant that is genuinely faulty but that none of the three tiers report stays in the dataset, labelled `undetected_by_construction`. These instances measure the detector's ceiling. Removing them would inflate recall by selecting for what the system already finds.

## 5. Site selection and defect multiplicity

Sites are drawn from the eligible positions for the operator using a recorded RNG seed. The generator retains at most one site for each operator and seed model. Without this cap, large models would contribute many similar bridge-flow variants and the result would mainly report a model-size effect.

For `S03`, every source and target endpoint of a sequence flow is eligible; one endpoint is selected per seed. Repointing it can produce reachability findings in addition to the primary `R005` or `R006`, but these are consequences of the same dangling reference rather than separately injected defects. For `F01` and `F02`, an eligible position is a structured gateway region. The split has at least two outgoing branches, the matching join has the same gateway type and at least two inputs, and every branch reaches one distinct join input without bypassing the join. `F03` additionally requires a parallel join immediately before an end event. `F04` removes an internal flow that is a directed bridge: after its removal, the target is unreachable from every start and the source cannot reach an end. The local RNG derives from the dataset seed and seed identifier. In the current `v1.0`, the generator retained 43 S03, 20 F01, 33 F02, 3 F03, and 43 F04 single-defect variants. `applicability.json` records eligible and selected soundness sites; every selected S03 site is recorded in its ground-truth entry.

Three multiplicity regimes, populated by design rather than by sampling:

- `k=1`, one defect in isolation, for per-class detection.
- `k=2` in disjoint subgraphs, for whether repair handles several findings at once.
- `k=2` sharing an element or region, for interaction between repairs.

The third regime is the only one under which the `max_repair_iters` sweep can separate its budgets, so it is not a marginal stratum.

An injection footprint contains its declared site and immediate control-flow neighborhood. Disjoint pairs have non-overlapping footprints; interacting pairs overlap. Candidate pairs must share a defect class. Operator-pair groups are sampled before concrete sites, preventing operators with many eligible locations from dominating selection. Both mutations must remain present after their combined injection, and the combined inverse plan must restore the seed. `S01+S02` is allowed under the dataset's operator contract: it removes both boundary events and expects both configured checker findings. Its classification depends only on whether the two local neighborhoods overlap. For STRUCT/SOUND, `v1.0` retains one disjoint and one interacting pair per seed. It additionally contains 37 human-verified disjoint SEM+SEM pairs; six seeds had no technically valid pair with non-overlapping footprints. All 123 stored pairs replay and all inverse plans restore their seed.

## 6. Semantic layer protocol

A description underspecifies its model: the model may hold detail the text omits, and the reverse. A semantic defect must therefore contradict a statement the text makes explicitly, and the record must point at that statement. PMo descriptions carry one sentence per line, so a line index identifies it.

The asserted relation is drawn from a closed vocabulary, which lets both sides of the contradiction be checked on the IR:

| operator | relation | automatic check |
|---|---|---|
| `M01` | `exists_task(label)` | holds in the seed, fails in the variant |
| `M02` | `precedes(a, b)` | holds in the seed, reversed in the variant |
| `M03` | `branch_condition(gateway, condition)` | present in the seed, negated in the variant |
| `M04` | `exists_path(from, event)` | present in the seed, absent in the variant |
| `M05` | `distinct_labels(a, b)` | distinct in the seed, colliding in the variant |
| `M06` | `reaches(end_state)` | reachable in the seed, unreachable in the variant |
| `M07` | `additional_action(flow, action_template)` | the mapped branch must not retain an extra copy of an existing business action |

Renaming to a synonym is not a defect, so `M05` applies only when the substituted term names a different object elsewhere in the description.

`M07` source records are commission variants: they add an action in addition to
otherwise-correct behavior. E8 reverses that verified commission and evaluates
the policy/prohibition refinement by checking that the extra action is absent.
The open-world description may contain harmless implementation detail that it
does not mention, so silence is never evidence of applicability. An M07 case
needs strong textual/domain evidence that the added action is forbidden,
contradicts an explicit required outcome, repeats a materially non-idempotent
action, or produces mutually inconsistent business outcomes. The mapping
identifies an existing branch flow and business-action template; the plan
contract proves only that exact edit, not its semantic truth. `instead of`
cases remain M05.

Each `SEM` record adds:

```json
"anchor": {
  "description_line": 7,
  "relation": "precedes('Check invoice', 'Approve payment')",
  "violated_by": "M02"
}
```

The generator checks three things without human input: 
- the relation holds in the seed, 
- it fails in the variant, 
- the variant still passes tiers 1 and 2. 

A variant failing the third check measures tier 1 rather than tier 3, so it is either repaired structurally (reconnect the flow) or discarded.

Cited description lines, relation contracts, and BPMN mappings form part of
the versioned construction record. [LLM assistance during
construction](#8-llm-assistance-during-construction) covers how a model may
assist with proposing them and the resulting limitation.

### Semantic mutation protocol for dataset v1.0

The semantic protocol separates applicability from materialisability. Applicability
asks only whether the description contains an explicit mandatory claim and an
unambiguous BPMN mapping for the operator. `not_applicable` means only that
such a claim or mapping is absent. It does not mean that a planner is limited,
or that a candidate would interfere with structural or formal validity; those
are materialisation outcomes.

A candidate is materialised only when all five gates pass: the relation-plan
contract, XML/IR round-trip, Tier 1, Tier 2, and the inverse plan. The semantic
error is defined by the stored evidence, `required` claim, relation, and
operator contract. All 198 published singles were human-verified; `01-M06`
was excluded because it also produced Tier-1 `R007`, and `11-M06` was removed
because it was byte-identical to the more specific `11-M04` case. Difficulty was not
persisted and is therefore not used for stratification or scoring.

The dataset contains all 43 eligible seeds. E1–E5 use frozen, paired selection
panels and may reuse only records with matching input, prompt, model, harness,
reasoning, IR, and converter metadata. E6 is the complete confirmatory panel.
The exact panels and reuse provenance are stored in `experiments/specs/runs/`
and `experiments/results/`; they do not support a claim of generalisation to
unseen source models.

## 7. Refinement instances

E8 measures requirement-driven process model enhancement/refinement. It does
not measure defect detection. Given seed `M` with description `D`, hold out the
verified anchor sentences as `D_extra` and keep the rest as `D_core`. Apply the
inverse of their required behavior to produce `M_core`. Depending on the case,
this can remove behavior, reverse an ordering, change a branch condition,
break a path or outcome, or add an unwanted action.

The model receives `M_core` and `D_extra` as a new chat instruction. It does
not receive the reference model, a finding, or the oracle plan. Its task is to
change the model so that it satisfies the new instruction. Ground truth is `M`
itself, but exact XML or exact oracle operations are not required.

E8 reuses the stored injection and inverse operations only to construct and
audit its cases. Semantic validation does not perform these operations; it
only reports findings. The evaluated model does not see the stored operations
and can produce any equivalent edit that satisfies the instruction.

`M_core` must be sound and free of tier-1 findings. It must also carry no
technical residue of its construction, such as dangling flows, invalid lane
references, or conditions that refer to removed elements. These checks run on
the IR.

The distinction is informational. In detection, the system receives the
mutated diagram and the complete description, including `D_extra`. It must
report the contradiction and its location, but it does not edit the model. In
repair, it receives a detected and validated finding and must remove that
problem. In E8, it receives no finding. `D_extra` arrives as a change request,
and the system must implement it directly.

The construction therefore looks like restoration when compared with the
hidden seed. From the evaluated model's perspective, it is a new requirement.
E8 is consequently a synthetic requirement-driven refinement benchmark, not a
benchmark of organic user changes. This limitation and the construction method
must be reported together.

Scoring adds one measure the repair experiments lack: preservation of what was not requested. Report the share of `M_core` elements surviving unchanged, label stability, and soundness after the edit, alongside `GED(result, M)`. A refinement that adds the right task while rewriting half the model is a poor refinement.

## 8. LLM assistance during construction

A language model may propose the `D_core` / `D_extra` split, identify which
elements realise `D_extra`, and propose anchor relations of the [semantic
layer protocol](#6-semantic-layer-protocol). For refinement, the original PMo
model remains the target. For injected semantic defects, the resulting
versioned evidence and relation contract define the constructed test case.

For a semantic relation that does not fit a conservative deterministic mutation
template, a language model proposed a case-specific injection plan and its
inverse using the existing `AtomicEditOp` vocabulary. Human verification, not
the proposal, established inclusion. The final ground-truth record stores the
exact operations and evidence needed to replay and audit the case; intermediate
prompts and duplicate candidate files are intentionally not part of the dataset.

For M01, deletion runs as code rather than as a model call. Its inverse is a
deterministic oracle used for construction checks only.

The assisting models were `gpt-5.6-luna` and `gpt-5.6-terra`. This creates a
possible construction-family bias and is reported as a limitation. The final
cases remain independently executable because their injections and inverses
are stored directly in ground truth.

Report how many proposed cases passed or failed each deterministic construction
gate. This is a construction statistic, not evidence of independent semantic
annotation.

## 9. Reporting

Results are reported per defect class. An aggregate over the classes is a weighted average whose weights are the class proportions in the dataset, and I fixed those proportions when composing it. Generating twice as many `STRUCT` instances would raise the aggregate figure without any change to the system. The aggregate therefore describes the dataset composition and not the detector.
