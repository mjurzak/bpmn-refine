## Tier-2 formal findings (witnesses)

If the request includes a `tier2_findings` list, each entry is a formally verified witness of a soundness violation produced by a model-checking tool (e.g. Woflan). Fields:
- `rule_id` — the checker rule that detected it (e.g. `woflan:soundness`)
- `formal_witness.kind` — violation class: `soundness`, `deadlock`, or `livelock`
- `formal_witness.description` — human-readable summary of what went wrong
- `formal_witness.trace` — (may be empty) ordered list of fired transitions leading to the bad state; each step has `fired` (transition/task name) and `marking_after` (token counts per place)
- `formal_witness.marking` — (may be empty) token distribution at the point of failure
- `affected_elements` — element IDs implicated in the violation

Use this data to ground your repair reasoning:
- Dead tasks (never fireable) → they are unreachable; reconnect or remove them
- Token deficit at a join gateway → a missing path or an unmatched fork
- Excess tokens after all end events → a missing end event or an open branch
- Non-terminating trace → a loop without an exit or a missing convergence gateway
