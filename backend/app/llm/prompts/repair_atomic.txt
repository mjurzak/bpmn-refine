## Issue representation

Each issue contains `rule_id`, `severity`, `tier`, `source`, `message`, and,
when localized, `affected_elements`.

Tier-2 issues are formally verified findings and may include `formal_evidence`:
- `kind` — the formal violation class
- `dead_elements` — BPMN elements that can never execute
- `uncovered_elements` — BPMN elements outside the relevant sound component
- `counterexample_traces` — one or more execution paths, expressed only as BPMN IDs
- `marking` — a localized token distribution, when available

Use the tier-2 message, evidence, affected BPMN elements, and diagram structure
to determine the smallest repair. The `source` identifies which configured
formal checker produced the result; do not assume a particular checker. Never
invent or reference formal-model elements that are absent from the BPMN IR.

## Connectivity issues

For a plain structural issue about a disconnected element, pick one of:
- Element carries intent the process still needs → `add_flow` to wire it in
- Element is a leftover, or its outcome is already covered elsewhere → `remove_node`

Never `add_node` an element that already exists, and never `change_node_type` to
dodge a connectivity rule — retyping an orphan leaves it just as disconnected.

## Other open issues (background only)

The request may include `other_open_issues` — findings that are open on the same
diagram but are **not** your assignment this round. They may include errors
scheduled for later dispatcher iterations. Treat them as background context:
- Do not fix them in this response. The dispatcher revalidates the diagram and
  assigns remaining errors in later rounds.
- Do use them to avoid making them worse. If the natural fix for your assigned
  issue would aggravate one of them, pick a different fix of the same size.

Your task is to produce the smallest ordered EditOp list that resolves the listed issue.

Rules:
- Fix only the issue listed. Do not change anything else.
- Prefer local edits over broad rewrites.
- Preserve element IDs unless an ID conflict forces a rename.
- Use `node_ids` only for node-targeting operations, and `flow_ids` only for flow-targeting operations.
- If the issue cannot be fixed without additional business context, return an empty `ops` list.
- Return ONLY a JSON object with one key:
    "ops" - the ordered EditOp array to apply
